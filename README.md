# 転職活動トラッカー

会社名・会社情報・応募経路・選考日程・面接の印象をまとめて管理する個人用の転職活動記録アプリです。
Next.js + Supabase で作られており、ログインすればどの端末のブラウザからでも同じデータを見られます。

## 機能

- 会社ごとに記録: 会社名、会社情報(自由記述)、企業サイトURL、応募経路
- 選考ステータスを複数登録: カジュアル面談・書類選考・一次面接・二次面接・最終面接・内定/不合格/辞退など、それぞれに日程・所要時間・実施方法・面接官・会話内容・印象・結果を記録
- 「現在のステータス」は登録した選考ステータスから自動で算出(日程が一番新しいものが表示される)。別立ての管理は不要で、選考が進むたびに追加するだけ
- トップページで次の選考予定を一覧表示。会社名・登録情報でサーチ可能、選考ステータス順/選考日程順/更新順に並び替え可能
- 会社ごとにメモを2種類記録: その場のメモ(上書き保存、一覧・詳細どちらの画面からも編集可)と、詳細画面のタイムライン(保存するたびに新しい1件として蓄積される経過記録)
- メール+パスワードでログインし、データはユーザーごとに分離(Supabase の Row Level Security)

## セットアップ手順

### 1. Supabase プロジェクトを作成

1. https://supabase.com にアクセスし、Google アカウント (`mk.tsuchiya8@gmail.com` など) でログイン/サインアップ
2. 「New project」で新規プロジェクトを作成(プラン: Free で十分)
3. プロジェクト作成後、左メニューの **SQL Editor** を開き、[`supabase/schema.sql`](supabase/schema.sql) の中身を貼り付けて実行
   - `companies` テーブルと `interview_stages` テーブル、Row Level Security ポリシーが作成されます
4. 左メニューの **Project Settings → API** を開き、以下をメモ
   - `Project URL`
   - `anon public` キー

### 2. 環境変数を設定

```bash
cp .env.local.example .env.local
```

`.env.local` を開き、先ほどメモした値を入力:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=xxxxxxxxxxxxxxxx
```

### 3. ローカルで起動

```bash
npm install
npm run dev
```

http://localhost:3000 を開き、「アカウントを作成」からメールアドレスとパスワードでサインアップ → 確認メールのリンクをクリック → ログイン。

### 4. どの端末からもアクセスできるようにする(任意)

ローカルの `npm run dev` は自分のPCでしか開けません。スマホなど他の端末からも使いたい場合は Vercel に無料でデプロイできます。

1. https://vercel.com にログイン(GitHubアカウント連携が簡単)
2. このプロジェクトを GitHub リポジトリに push
3. Vercel で「Add New Project」→ そのリポジトリを選択
4. 環境変数 `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` を Vercel の設定画面で入力
5. デプロイ後に発行される URL をどの端末からも開けば、同じアカウントでログインするだけでデータが同期されます

Supabase の **Authentication → URL Configuration** で `Site URL` をデプロイ後のURL(例: `https://your-app.vercel.app`)に設定しておくと、確認メールのリンクが正しく機能します。

### 5. 会社名サジェストを国税庁データで強化する(任意・推奨)

会社追加フォームの会社名サジェストは標準で2つのソースを使います:

- **登録済みの会社**: 自分がこれまで登録した会社(前株/後株を区別せず検索)
- **Web検索候補**: Clearbit(無料・登録不要)。企業サイトURLの自動入力に使われますが、日本の中小企業のカバー率は低いです

これに加えて、**国税庁の「法人番号公表サイト Web-API」** を設定すると、日本のほぼ全ての登記法人を前株/後株を区別せず検索できるようになります(ただしURLは含まれません — 登記情報なのでURLは元々存在しないため)。

**登録方法**(この作業はご自身のお名前・電話番号・メールアドレスを使うため、ご自身で行ってください):

1. https://www.invoice-kohyo.nta.go.jp/web-api/index.html#cmsprereg を開く
2. 「個人」向けの申込みフォームから、氏名・電話番号・メールアドレスを入力して届出(無料、費用はかかりません)
3. 後日、国税庁から**アプリケーションID(13桁)**がメールで届きます
4. `.env.local` に追記:

```
NTA_APPLICATION_ID=xxxxxxxxxxxxx
```

5. 開発サーバーを再起動すれば、会社名入力時に「国税庁 法人番号(公式)」の候補が出るようになります

設定しない場合でも、他の2つのソース(登録済みの会社・Web検索候補)だけで問題なく動作します。

### 6. 通勤経路を表示する(任意)

会社の「勤務地」から最寄駅を自動取得する機能は、**登録不要・無料**の公的API(国土地理院の住所検索 + HeartRails Express)で動くため、追加設定は不要です。

「設定」ページで自宅最寄り駅を登録すると、各社の詳細ページに「経路を確認」ボタンが出て、自宅最寄り駅↔会社最寄り駅の経路を確認できます。これには **駅すぱあと API** の無料プランの登録が必要です:

1. https://api-info.ekispert.com/form/free/ を開く
2. 会社名欄に「個人」、お名前・メールアドレス・利用ドメイン(デプロイ後のURL、無ければ `localhost` 等)を入力して申し込み(無料)
3. 3営業日以内にアクセスキーがメールで届きます
4. `.env.local` に追記:

```
EKISPERT_ACCESS_KEY=xxxxxxxxxxxxx
```

5. 開発サーバーを再起動

**注意**: 駅すぱあとAPIの無料プランは、経路検索結果を「駅すぱあと for Web」への確認用リンクとして返す仕様のため、アプリ内には所要時間の数値ではなく「経路を確認」ボタン(クリックすると駅すぱあとのページが新しいタブで開き、そこで時間が確認できます)という形になります。設定しない場合はボタンの代わりに案内メッセージが表示されます。

### 7. Googleカレンダー自動連携(任意)

「設定」ページでGoogleカレンダーと連携すると、**選考ステージの日程を登録したときに、自動でGoogleカレンダーに予定が作成・更新・削除されます**(手動でリンクを押す必要はありません)。連携していない場合は、代わりに「Googleカレンダーに追加」リンク(クリックで予定作成画面が開く、登録不要の簡易版)が表示されます。

自動連携には **Google Cloud のOAuthクライアント登録**が必要です。他の連携(メール登録だけ)より少し手間がかかります:

1. https://console.cloud.google.com/ を開き、Googleアカウントでログイン
2. 上部のプロジェクト選択メニューから「新しいプロジェクト」を作成(名前は何でもOK、例: `job-hunt-tracker`)
3. 左メニュー「APIとサービス」→「有効なAPIとサービス」→「+ APIとサービスを有効化」を開き、**「Google Calendar API」**を検索して有効化
4. 左メニュー「APIとサービス」→「OAuth同意画面」を開き:
   - User Type: 「外部」を選択(個人利用ならこれでOK)
   - アプリ名・サポートメール・デベロッパーの連絡先メールなど必須項目を入力して保存
   - 「テストユーザー」に自分のGoogleアカウントのメールアドレスを追加(公開審査を受けない限り、テストユーザーとして登録した自分のアカウントでのみ動作します)
5. 左メニュー「APIとサービス」→「認証情報」→「+ 認証情報を作成」→「OAuth クライアント ID」を選択:
   - アプリケーションの種類: 「ウェブ アプリケーション」
   - 「承認済みのリダイレクト URI」に以下を追加:
     - `http://localhost:3000/api/auth/google/callback`(ローカル開発用)
     - デプロイ後のURLがあれば `https://your-app.vercel.app/api/auth/google/callback` も追加
   - 作成すると **クライアントID** と **クライアントシークレット** が表示されます
6. `.env.local` に追記:

```
GOOGLE_CLIENT_ID=xxxxxxxxxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxxxxxxxxxxx
```

7. 開発サーバーを再起動し、「設定」ページの「Googleカレンダーと連携する」ボタンから連携してください

設定しない場合でも、アプリは問題なく動作します(自動同期の代わりに手動の「カレンダーに追加」リンクが表示されます)。

## データモデル

- `companies`: 会社名、会社情報、企業サイト、応募経路、年収、勤務地、最寄駅、リモート可能日数(週1〜5日)、福利厚生、残業時間の目安、求人要件、志望順位・志望理由、決め手・懸念点、その場のメモ(上書き保存。一覧・詳細どちらの画面にも表示)
- `interview_stages`: 会社に紐づく選考ステータス(ステータス名、選考日程、所要時間、実施方法、面接官名、会話内容、面接の印象、自由記入メモ、結果、Googleカレンダー予定ID)。「現在のステータス」はここから自動算出され、別のテーブルは持ちません
- `company_memos`: 会社に紐づくタイムライン(詳細画面のみに表示)。保存するたびに1件ずつ蓄積される経過記録で、上の「その場のメモ」とは別枠
- `google_calendar_connections`: Googleカレンダー連携のリフレッシュトークン(ユーザーごとに1行)
- 自宅最寄り駅: テーブルではなく Supabase Auth のユーザーメタデータに保存(「設定」ページから登録)

いずれも `user_id` で所有者を区別し、Row Level Security で本人のデータしか読み書きできません。

**既にテーブルを作成済みの場合**は、[`supabase/schema.sql`](supabase/schema.sql) 末尾の `alter table` コメント行(コメントを外して)を SQL Editor で実行し、新しい列を追加してください。
